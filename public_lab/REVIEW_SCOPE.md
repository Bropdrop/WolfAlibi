# Quorvane public review scope

Permission for this exercise covers the documented offline WolfAlibi synthetic challenge environment on a machine you control. The cases use fictional requests and published public keys. Use a disposable directory for each review. The canonical verifier runs disconnected. The optional Linux target controls create temporary local state.

| Actor | Control assumed | Consequence for review |
| --- | --- | --- |
| Reviewer submitting evidence | All submitted bytes, including JSON names, encoding, request terms, receipts, historical inquiries and purported checkpoints. The reviewer can edit local copies of reference files. | Select public inputs from a separately identified revision. Compare the fixed inventory and record the layer and reason for each decision. |
| Bundle publisher | Can replace the program, evidence, manifest and reported answers together. | A hash shipped alongside the files cannot independently authenticate the publisher. Obtain the expected Git commit and tree or archive digest through a channel you already trust. A reproducible build establishes byte agreement for those inputs. |
| Signer or custodian | A compromised owner, target, supervisor, auditor or witness may sign misleading statements or lose state. | The profile assumes genuine keys and the stated roles. It cannot establish that independently administered parties controlled them, a signer observed everything, or an alternative history never existed. |
| Local operator | Can replace Python, edit the tests or browser, change storage and clocks, or fabricate a report. | Reviewers trust their local execution environment. Reproduce findings on a separate trusted checkout. Imported reports and exported findings are reviewer statements. |

Ed25519 forgery and possession of independently held private keys are outside the reviewer model. Cross-UID custody is `UNSUPPORTED`. Independent anchor custody, coordinated rollback and real settlement remain unassessed. Production and confinement are `BLOCKED`. Certification is `NOT_ISSUED`.

## Permitted activity

Use the included fictional evidence, local public verifier and documented disposable synthetic controls. Inspect the files, rerun the matrix and record discrepancies. Keep optional browser file serving on loopback. This scope excludes real banks, payment processors, schools, public infrastructure and unrelated third-party systems. It supplies no permission to probe those services. Use only synthetic data, published public keys and local filesystem paths.

## Reporting a finding

1. Record the exact revision or archive SHA-256 you obtained independently, the challenge ID, fixture digest, Python version and platform.
2. Run the command in the selected challenge. Preserve the JSON decision and exit status. Compare the expected claim, observed claim and decision reason. A crash, missing dependency or partial run is an execution finding.
3. In the Financial Security Challenge, select the same case, compare the report and export a local finding JSON. Record whether the result came from your execution or the packaged reference run. Redact usernames, private paths and identifying free text. Include only public fixture references and fictional records.
4. Keep the finding on disk. If you and the repository owner separately agree on a reporting channel, share the reviewed file there. The explorer has no upload or hosted submission endpoint.

Keep live credentials, private keys, customer data, real financial records and student information out of files and reports. This exercise offers no formal certification, bug bounty or reward terms. The repository owner has not selected an open-source license. Public access and this testing scope do not grant redistribution rights.
