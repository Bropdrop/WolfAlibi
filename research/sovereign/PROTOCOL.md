# WT-SWARM-005 protocol and threat model

## Stationary protected target

One logical target has a provisioned native gate identity and one ephemeral execution-enforcement session. The owner enrolls that session's public boot key, the native gate public key, and the two executor public keys. Each executor also has a distinct pinned TLS identity. The trusted fixture provisions public pins independently of the target database. A lab owner signer controls grants. A separate lab evidence signer controls synthetic assessments. Each signer has a private key, mount namespace and mutually authenticated loopback endpoint. Separate controller certificates authorize access to each signer. The harness drives their decisions. This exercises credential and process separation under a trusted provisioner.

Three pinned etcd 3.5.16 members run Raft on six independently interruptible directed TLS peer links. Member credentials use a different CA from client credentials. Member data directories are private to each service. Each client authenticates the destination certificate, including a fingerprint check before sending its directory token. Roles restrict publishing and reading the governance prefix. The trusted directory writer submits a compare-and-put for an empty slot with an existing predecessor. RBAC grants prefix write permission. Append-only discipline therefore depends on the publisher, in addition to the checks enforced at the target.

The owner signs the logical target, native gate, boot, index, predecessor record digest, epoch, holder key, transition kind and revoked grant identifier. An activation advances the epoch by exactly one. A revocation retains the epoch and current holder. A CAS winner is pending. **The effective transition instant is the commit of its installation transaction at the protected target.** The acknowledgment binds the order digest, slot, epoch and counter at that instant. Anyone can relay a valid pending transition. A directory leader, publisher or coordinator cannot sign it. A malformed slot can obstruct progress.

For a new effect the target reads its current prefix from quorum, compares its installed head, and checks for a successor. On a pending transition it installs it under its own native writer and requires a retry. A quorum outage at admission denies the attempt. The target signs the prepared action and stores its epoch and directory head. The owner separately signs the native grant and the exact request permit. The latter binds the target, native gate, boot, epoch, head, executor, operation, request and grant digests. The executor signs the permit and request digests.

The target takes its native SQLite writer, checks its own protected state and the authenticated TLS executor, and validates the request against the effective local head. It rechecks that binding inside the settlement transaction. The counter, consumed native grant, exact request, original receipt and boot-signed settlement endorsement commit together. The native clock and execution deadline checks run again immediately before commit. Transition installation and effect settlement use the same local writer; neither operation uses a directory transaction touching the counter. A quorum write during an in-flight settlement can take effect at the target only after the writer releases. A fully admitted operation can finish while all directory members are stopped. Its acknowledgment can be lost.

The active target stores a digest of its tables and monotonic clock in process memory. It checks the digest before settlement and recovery. A replacement process has a new boot key. Initialization requires the original unused native schema and an empty operations table. A used or cloned target cannot bootstrap through this path. Total loss of the enforcing process therefore stops new execution on that target. Operators must preserve ambiguous requests. Authorizing a replacement genesis after such a loss is outside the protocol.

## Evidence and reconciliation

At enrollment the owner binds a reader certificate fingerprint to one verified, frozen native request and grant. The target admits that ACL entry under its current authority and stores it locally. Read-only recovery checks the principal, exact binding, live state seal and operation. It returns the original receipt for COMMITTED. A prepared exact request whose enrolled grant has a durable revocation yields NOT_COMMITTED. Insufficient evidence yields UNRESOLVED. A TLS failure carries no definitive outcome.

The independent laboratory observer takes a read-only SQLite snapshot in the target's storage domain and queries the directory through a separate read-only credential. It reads the installed prefix through all three client endpoints. Those linearizable reads can consult the same quorum. They are not three independent Byzantine witnesses. The offline verifier checks the owner-signed chain, target-signed installation boundaries, and the interval in which every increment occurred. It validates native action, verifier assessment, grant, executor endorsement, original receipt, target counters, request identity and uniqueness. It checks each measured recovery against that reconstruction. Independent custody of the observer's pins is required. The archive checksum authenticates the delivered copy against the digest supplied separately.

A historical reader runs in a separate namespace with its own TLS key and a frozen observer snapshot supplied through a private provisioning pipe. It has no target, directory or execution credentials. It verifies the observer pins and the full snapshot before listening. After the active target exits, the authorized reader can retrieve the original receipt or durable revocation conclusion from that snapshot. A pending request at the snapshot remains unresolved there. This service is limited to captured history. Direct supervision of target storage for evidence collection is a Tier A lab privilege. The execution and authority services never mount one another's state.

## Failure and custody boundaries

| Boundary | Scope |
|---|---|
| Crash and omission | Three distinct Raft processes tolerate one unavailable member for new ordering. A minority cannot advance linearizable state. The target may finish a transaction admitted before disruption. The target's own transaction serializes effective authorization. |
| Storage | SQLite DELETE journal and FULL synchronization on ordinary local storage, one native counter. The trial checks process interruption, unavailable journal, live state restoration, a used-state clone, and rollback of the directory key together with the target image. A single trusted live boot remains during the coordinated rollback test. |
| Byzantine | Owner, provisioner, target enforcement, native key custody, observer, kernel and directory quorum are trusted. Coordinators may resend, lose replies or present conflicting proposals. A publisher can obstruct progress or corrupt its prefix. Raft does not tolerate Byzantine quorum members. A compromised owner, target key or host administrator is outside the qualification. |
| Relocation | Only executor authority moves. No network protocol transfers the protected target or makes a restarted or cloned counter writable. A cold rollback of the entire machine and all trusted witnesses, two independently writable replicas, hardware power failure and physical partitions have no qualification here. |
| External assurance | Lab evidence uses a synthetic fixture. The owner service uses a disposable key. HERCULES, genuine Shirudo, actual owner approval and measured independent custody are separate qualifications. |

## What the inherited experiment established

At the pinned 004A revision, research/schism/storage.py checks device and inode, requires DELETE journal and at least FULL synchronization on main, attaches control and witness, requires DELETE on both and sets each to FULL. research/continuity/destination.py also attaches retired control read-write and retired witness read-only, checks rollback-journal modes, sets FULL and checks the destination target and retired control device. BEGIN IMMEDIATE covers the retirement claim, import, destination checkpoint and witness. This relies on local SQLite locking, rollback journals and filesystem synchronization semantics. Process interruption and replay tests establish the demonstrated single-host behavior. They supply no evidence of atomic commit across independent filesystems, Raft and SQLite, or physical power loss.
